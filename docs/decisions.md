# Decisions

One line per owner decision: date · number · decision · reason. The open ones are listed in [`plan/00-INDEX.md`](plan/00-INDEX.md).

- 2026-10-28 · D1 · Repo `meridian-dashboard-nyc`, package `meridian_dashboard_nyc` · Package matches the distribution name, so the build backend needs no module-name override.
- 2026-10-28 · D2 · Event logs keep open items, the newest deed per lot and the newest certificate per building, plus everything since one fixed start date, 2025-01-01, set once in `config.py` · Keeps the first pass small; history is added later by moving the date back.
- 2026-10-28 · D3 · Keep the two newest pulls of each dataset; `make daily` ends with `prune`, which runs only after every earlier step succeeded · Keeps disk small for the first pass; a failed run never removes the last good pull.
- 2026-10-28 · D4 · No email in v1; reviews and the daily digest go to an Inbox page on the dashboard, and email comes later as a subscription · The site collects and updates first; no email client, webhook or public address to build now.
- 2026-10-28 · D5 · Next.js + React + deck.gl over a MapLibre basemap; TanStack Query, Zustand and filters in the URL; Plotly for every chart, in Python and the browser · deck.gl handles the volume of map data; Python urban-form analyses hand Plotly figures straight to the dashboard; crawler rules keep a public site's hosting bill flat.
- 2026-10-28 · D6 · Laptop and Task Scheduler through Phase 8; from Phase 9 the pipeline and FastAPI on one small VM (cron), Next.js on Vercel, tiles on Cloudflare R2; map and lot pages public, Inbox, Sites, Review and Profiles behind sign-in · Nothing to host until there is something to show; the VM and R2 bill flat, and buyer profiles and reviews stay private.
- 2026-10-28 · D7 · You write the first one or two buyer profiles before Phase 8 · Once the lot card and metrics exist, every screen can name a real metric.
- 2026-10-28 · D8 · Twelve triggers: the ten proposed plus `zoning_changed` (from `zoning_tax_lots`) and `watched_buyer_bought` (deed buyer matches `watchlist.yaml`); every sale shows buyer and seller as recorded; company buyers flagged `buyer_is_company` · Adopted rezonings and other groups' purchases are signals you want, without guessing which LLCs belong together.
- 2026-10-28 · D9 · `claude-opus-5-5` for every step; after Phase 8c the eval also runs on Opus at `low` effort and on Sonnet 5.5, and a step switches only when it holds quality · Start from the best quality and let measured results, not guesses, drive cost down.
- 2026-10-28 · D10 · The Meridian XYZ brand guidelines (`meridianxyz_website/brand-guidelines.md`): § 11.1 token sheet in `web/src/tokens.css`, § 4.5 ramps for maps and charts · Written for this dashboard; the app and www.meridianxyz.com read as one product.
- 2026-10-28 · D11 · Walking distance on an `osmnx` (OpenStreetMap) network from every lot to each destination kind, built in Phase 5; destinations chosen in the network spec; no straight-line approximations · Straight-line distance misstates access across rail yards, highways and water; the real network is cheap to compute once.
- 2026-10-28 · D12 · Deferred with D4 · Nobody receives email until email subscriptions are added.
- 2026-10-28 · D13 · No `territory` column; one database per city · NYC's tables stay clean; a second city adds its own dataset packages and files, and cross-city queries attach both.
- 2026-10-28 · D14 · Census demographics from the newest ACS 5-year release, by tract · ACS 1-year estimates are not published for tracts.
- 2026-10-28 · D15 · Urban-form metrics follow the nine-level ladder in `plan/08-URBAN-FORM.md`; levels 1–5 at lot and NTA grain in a new Phase 5.5; block grain, momepy, srai and a typology later · Start with simple metrics and add complexity one checked level at a time, through one registry so new techniques need no new plumbing.
- 2026-10-28 · D16 · Auth.js with Google and GitHub sign-in; guests browse without signing in; Next.js gives FastAPI a short-lived signed token and FastAPI checks it and the caller's tier · Free, no vendor, and the token flow is yours to see; sign-up is part of how customers are won.
- 2026-10-28 · D17 · "Nearby" for comps and nearby activity means a neighborhood: default the lot's own 2020 NTA, or chosen neighborhoods, or a lasso drawn on the map; each comp shows its metrics and their difference from the subject lot · Buyers think in neighborhoods, not radii; side-by-side metrics show what may sit behind a price difference.
- 2026-10-28 · D18 · Access tiers for accounts: guests browse without signing in; accounts unlock deeper views and their own profiles and Inbox; the details are in the owner's private notes · Kept out of the public repo.
- 2026-10-28 · D19 · Postgres as the app database: Docker on the laptop from Phase 7, the VM from Phase 9; only the Python side connects · The standard store for a multi-user app, on the flat-priced VM.
- 2026-10-28 · D20 · Deferred until Phase 9.5 · Accounts and payments come after the first delivery, when consulting calls for them.
- 2026-10-28 · D21 · The first delivery is Phases 0–9 with 5.5 and the full agent, live as a portfolio platform; Phase 9.5 when consulting calls for it; Phase 10 over time · Back end, front end, analytics and reporting on site changes are the foundation everything else builds on.
- 2026-10-29 · D22 · Keep the code simple: plain modules, module-level constants, and each library or tool added in the spec that first needs it. S001 has no Makefile, pre-commit hook or CI · A small scaffold that works comes first. Heavier tools arrive with the code that needs them.
- 2026-10-29 · D23 · The code stays in `src/meridian_dashboard_nyc/`, with `uv_build` as the build backend · The standard layout for an installable package. Tests import the installed package, as other code does.
- 2026-10-29 · D24 · All text follows `docs/WRITING_AND_COMMUNICATION_RULES.md`: Simplified Technical English (ASD-STE100) and general writing rules · One standard for docs, specs, docstrings, commit messages and the agent's output.
- 2026-10-29 · D25 · Commit locally while a spec is open. Push `main` once, when the spec is done and the owner has reviewed the change · The public `main` shows only finished work that passes its tests.
